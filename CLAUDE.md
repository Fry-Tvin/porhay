# Порхай — пересборка сайта с Тильды

Развлекательный центр во Владивостоке, ул. Державина 23. Задача: перенести сайт
с Тильды на свою вёрстку, **сохранив дизайн один в один** — владелице он нравится,
менять его нельзя.

## Что где лежит

| Папка | Что это |
|---|---|
| `porhai-eds/` | Исходный экспорт с Тильды. **Только для чтения** — эталон и источник картинок. |
| `porhai-new/` | Новая вёрстка. Здесь идёт вся работа. |
| `porhai-new/spec/` | Спецификация вёрстки, снятая с экспорта: координаты, стили, тексты по всем брейкпоинтам. |
| `porhai-new/assets/` | `style.css`, `img/` (пережатые картинки), `fonts/` (Evolventa). |

## Инструменты

Запускать из `porhai-new/`:

```bash
python extract_spec.py      # экспорт Тильды -> spec/*.json (уже снято, повторять не нужно)
python optimize_images.py   # картинки из экспорта -> assets/img/ в WebP
python build.py             # spec + шаблоны -> index.html
python make_standalone.py   # автономный файл для показа без сервера
python make_artifact.py     # файл для публикации по ссылке
```

Локальный просмотр — из корня `Таплинк/`:
`python -m http.server 8777`, дальше `/porhai-new/index.html` и `/porhai-eds/page34664661.html` для сверки.

## Главное правило

**Дизайн не трогаем.** Никаких «улучшу отступы», «поправлю цвет», «этот шрифт лучше».
Совпадение проверяется числами, а не на глаз. Допуск — 2 px.

Менять можно и нужно только то, что перечислено в разделе
«Что из аудита входит в пересборку, а что нет», группы A и B.

## Как читать спеку

`spec/page34664661.json` — массив блоков в порядке следования. У блока:

- `id` — идентификатор блока в Тильде (`rec…`), по нему же ищется оригинал;
- `kind` — что это за блок по-русски;
- `height` — высота артборда по брейкпоинтам;
- `background` — фон;
- `elements` — элементы зеро-блока с `geometry`, `styles`, `text`, `image`;
- `texts` / `images` — для обычных блоков Тильды, у которых нет свободного позиционирования.

### Брейкпоинты — читать внимательно

Ключи в `geometry` и `styles` — это `max-width` медиазапросов Тильды:

| Ключ | Когда применяется | Что там |
|---|---|---|
| `base` | ≥ 1920px | Исходный макет. Координаты лежат **только здесь**. |
| `1919` | 1200–1919px | **Основной десктоп.** Здесь верные кегли. |
| `1199` | 960–1199px | Планшет. |
| `959` | 640–959px | Крупный телефон. |
| `639` | 480–639px | Телефон. |
| `479` | < 480px | Узкий телефон. |

Две ловушки:

1. **Кегли брать из `1919`, а не из `base`.** В `base` H1 — 68px, но на реальном десктопе он 58px.
2. **Координаты из `base` нельзя подставлять напрямую.** Они заданы в системе координат
   макета Тильды и на странице пересчитываются. Пользуйтесь ими для понимания
   композиции и пропорций, а точные значения снимайте замером (см. ниже).

## Порядок работы над секцией

1. **Прочитать спеку блока** — состав, тексты, картинки, фон, высота.
2. **Снять эталонные координаты с оригинала.** Открыть
   `http://localhost:8777/porhai-eds/page34664661.html` и выполнить в консоли:

   ```js
   (() => {
     const rec = document.getElementById('recNNNNNN');
     const art = rec.querySelector('.t396__artboard') || rec;
     const ar = art.getBoundingClientRect();
     return [...rec.querySelectorAll('.t396__elem')].map(e => {
       const a = e.querySelector('.tn-atom'), s = a ? getComputedStyle(a) : {}, r = e.getBoundingClientRect();
       const im = e.querySelector('img');
       return {t: e.getAttribute('data-elem-type'),
         x: Math.round(r.left - ar.left), y: Math.round(r.top - ar.top),
         w: Math.round(r.width), h: Math.round(r.height),
         txt: (a && a.innerText || '').trim().slice(0, 60),
         img: im ? (im.getAttribute('data-original') || im.src || '').split('/').pop() : null,
         bgImg: s.backgroundImage !== 'none' ? s.backgroundImage.split('/').pop() : null,
         fs: s.fontSize, fw: s.fontWeight, lh: s.lineHeight, color: s.color,
         bg: s.backgroundColor !== 'rgba(0, 0, 0, 0)' ? s.backgroundColor : null,
         br: s.borderRadius !== '0px' ? s.borderRadius : null,
         tr: s.transform !== 'none' ? s.transform : null};
     });
   })()
   ```

   Замер делать при ширине артборда **1265px** — это тот же режим, в котором свёрстано
   уже готовое. Картинки лениво подгружаются, поэтому перед замером прокрутить до блока.

   **Важно про песочницу.** Сеть в этом окружении блокирует `static.tildacdn.com`,
   поэтому `Evolventa` на `porhai-eds` не грузится и браузер молча подставляет
   Arial — размеры текста (высота строк, перенос по словам) будут неверны, хотя
   расположение нетекстовых элементов (иконки, отступы, картинки) не пострадает.
   Если меряете что-то, зависящее от текста (перенос строк, высота блока с текстом),
   подменяйте шрифт через перехват запроса на локальный файл, иначе цифры соврут:
   ```js
   await page.route('**/Evolventa-Regular.woff', r => r.fulfill({ path: 'porhai-new/assets/fonts/Evolventa-Regular.woff' }));
   await page.route('**/Evolventa-Bold.woff', r => r.fulfill({ path: 'porhai-new/assets/fonts/Evolventa-Bold.woff' }));
   ```
   Playwright с Chromium в песочнице уже есть (`/opt/pw-browsers`, глобальный npm-пакет
   `playwright` в `/opt/node22/lib/node_modules`) — им и снимать замеры вместо консоли браузера.

   Та же сеть блокирует и карты (`yandex.ru/map-widget` отвечает 403 через прокси
   песочницы) — блок «Контакты» использует Яндекс-виджет с адресом в query-параметре,
   в песочнице рендерится плейсхолдером-«битой картинкой», это ожидаемо и не баг.
   Проверять реальную отрисовку карты можно только вне песочницы.

3. **Сверстать секцию** нормальным потоком: flex или grid, без абсолютного
   позиционирования содержимого. Абсолютно позиционируется только декор
   (кляксы, мелкие картинки) — он и в оригинале декор.
4. **Добавить картинки** в `DISPLAY_WIDTH` в `optimize_images.py` с шириной отображения
   и прогнать пережатие.
5. **Сверить числа** — открыть свою страницу и снять те же координаты. Расхождение
   больше 2px — дорабатывать. Сверять обязательно: высоту секции, позиции заголовка,
   подзаголовка и основного содержимого, кегли, цвета, радиусы.
6. **Проверить мобильную** — ширина 375. Требования: нет горизонтальной прокрутки
   (`document.documentElement.scrollWidth === clientWidth`), нет кликабельных элементов
   мельче 40×40, нет битых картинок.
7. **Пересобрать** — `python build.py`, при необходимости `make_artifact.py`.

## Что из аудита входит в пересборку, а что нет

Аудит дал 30 находок. Они делятся на четыре группы, и смешивать их нельзя.

### A. Делается молча — внешний вид не меняется

Никакого согласования не требуется, это просто часть качественной вёрстки.

- `lang="ru"`, семантика: `h1`/`h2`/`h3`, `nav`, `main`, `figure`, `figcaption`.
- Две битые «фигмовские» кляксы — локальные копии подставлены в `build.py`, словарь `BIT`.
- Картинки только WebP, под реальный размер отображения ×2.
- Шрифт Evolventa лежит локально, без обращения к CDN Тильды.
- Разметка LocalBusiness и FAQPage — при вёрстке контактов и FAQ.
- Цели Метрики и пиксель VK — при подключении аналитики.
- Чистые адреса страниц без зависимости от `.htaccess`.
- Кликабельные элементы не мельче 40×40 на мобильной.

### B. Обязательно по закону — добавляет видимые элементы

Без этого сайт нельзя публиковать и нельзя рекламировать. Элементы новые, поэтому
делать их строго в фирменном стиле: те же цвета, шрифт и скругления, минимальный размер.

- Чекбокс согласия на обработку персональных данных в каждой форме.
- Страница политики конфиденциальности и ссылка на неё в подвале.
- Реквизиты организации в подвале.
- Баннер согласия на cookie.

### C. Заблокировано на владелице — не выдумывать

- Актуальные цены. В экспорте они за 2023 год. Переносить как есть, вести список того,
  что требует обновления, и показывать заказчику.
- Тексты вроде «Выпускные 2023 не за горами» — пометить, но не сочинять замену.
- Реквизиты, ИНН, форма собственности.
- Что делать с партнёрами в Instagram.
- Отзывы в 2ГИС и на Яндекс.Картах.

Исключение: замазать номер телефона клиента на скриншоте отзыва
(`images/tild3139-6336-4961-b439-303832396662__photo_2023-02-19_16-.png`) можно и нужно
сразу — это утечка персональных данных третьего лица.

### D. За рамками пересборки — отдельный этап после переезда

Это уже изменение дизайна и логики, а не перенос. Сюда **не лезем**, пока идёт вёрстка.

- Календарь свободных дат.
- Поля «дата» и «повод» в форме заявки.
- Вилка цен или калькулятор на странице корпоративов.
- Подарочные сертификаты.
- Сбор базы и напоминания о дне рождения.
- Кликабельный телефон на первом экране мобильной версии.
- Дублирование текстов отзывов рядом со скриншотами.
- Блок «как добраться», возрастные ограничения.

Почему отдельно: если менять дизайн одновременно с переносом, потом невозможно понять,
от чего изменились заявки — от новой скорости или от нового блока. И владелица теряет
тот сайт, который ей нравится, не успев его увидеть на новом месте.

## Чего не делать

- Не менять композицию, цвета, шрифты, размеры.
- Не «причёсывать» тексты — переносить дословно, включая опечатки вроде «Cтильные»
  (там латинская C) и «лишний траты». Исправлять только по согласованию.
- Не тащить jQuery и никакие библиотеки. Сейчас на странице 0,3 КБ скрипта, так и держать.
- Не трогать `porhai-eds/` — это эталон.

## Что осталось на главной

  не перекрывать плавающую кнопку связи справа), тёмный фон подвала, кнопка

Дальше — остальные 11 страниц. Шапка, подвал, FAQ, ленты и карточки у них общие
с главной, так что после главной работа идёт заметно быстрее.
